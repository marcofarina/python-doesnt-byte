# Archivio e Database — sandbox di test

Pagina di verifica dei pannelli «Archivio» e «Database». Non è linkata dalla
sidebar (`unlisted: true`). Il frontmatter dichiara `archivio: [punti.json,
studenti.json]` e `database: archivista/registro-punti`.

Cosa controllare:

- **Desktop:** in testa alla colonna dell'indice c'è il pulsante «Archivio · 2 file».
  Aperto, il pannello prende il posto dell'indice, ha una scheda per file e resta
  fermo mentre il testo scorre. Esc (col focus nel pannello) lo chiude.
- **Telefono:** pulsante flottante in basso a sinistra; il pannello sale fino a metà
  schermo e si chiude con la X, con Esc e con un tocco fuori.
- **Fra le pagine:** con il pannello aperto, passa a un'altra pagina che dichiara
  l'archivio e torna qui: il pannello è ancora aperto, sulla stessa scheda.
- **LIM:** «Apri in una nuova scheda» apre `/archivio?file=…` con il file scelto.

## Il pannello Database

Piano `pm/piano-2026-10-pannello-database.md`. Cosa controllare:

- **Desktop:** sotto «Archivio» c'è il pulsante «Database». Si apre un pannello alla
  volta; chiusi entrambi torna l'indice. Aperto prima di ogni run, il pannello dice
  «Stato iniziale» e mostra le tabelle del seed.
- **Dopo un run:** il pannello mostra le tabelle come le ha lasciate l'ultimo blocco
  eseguito, con il suo nome in testa (cliccandolo si torna al blocco), e passa alla
  prima tabella cambiata. Righe nuove, modificate (cella cambiata marcata) e tolte
  (barrate, in coda).
- **Pannello chiuso:** un run che scrive accende il pallino sul pulsante, con
  l'`aria-label` «N modifiche da vedere»; aprendo il pannello il pallino sparisce.
- **Al caricamento:** il blocco `hideQuery` qui sotto gira da solo e non tocca il
  pannello.
- **Telefono:** il pulsante flottante apre un pannello con due schede, «Archivio» e
  «Database», e porta il pallino.
- **Fra le pagine:** andando su un'altra pagina e tornando qui, il pannello riparte
  da «Stato iniziale».

```sql live dataset=archivista/registro-punti hideQuery
SELECT nome, casa FROM studente WHERE anno = 3;
```

### Una riga nuova

```sql live dataset=archivista/registro-punti title="Una riga nuova"
INSERT INTO assegnazione (studente, punti, professore)
VALUES ('Harry Potter', 10, 'Silente');
```

### Una riga modificata

```sql live dataset=archivista/registro-punti title="Una riga modificata"
UPDATE assegnazione SET punti = 20 WHERE id = 9;
```

### Righe tolte

```sql live dataset=archivista/registro-punti title="Righe tolte"
DELETE FROM assegnazione WHERE professore = 'Piton';
```

### Errore a metà

La prima istruzione resta scritta, la seconda fallisce: il pannello dice «finito
con un errore» e mostra Lupin fra i professori.

```sql live dataset=archivista/registro-punti title="Errore a metà"
INSERT INTO professore (nome) VALUES ('Lupin');
INSERT INTO assegnazione (studente, punti, professore)
VALUES ('Nessuno', 1, 'Lupin');
```

### Tabella creata e tabella tolta

```sql live dataset=archivista/registro-punti title="CREATE e DROP"
CREATE TABLE casa (nome TEXT PRIMARY KEY, fondatore TEXT);
INSERT INTO casa VALUES
    ('Grifondoro', 'Godric Grifondoro'),
    ('Serpeverde', 'Salazar Serpeverde');
DROP TABLE assegnazione;
```

### Stateful

Eseguito due volte, alla seconda è nuova solo la riga del secondo run.

```sql live dataset=archivista/registro-punti stateful title="Stateful"
INSERT INTO assegnazione (studente, punti, professore)
VALUES ('Ron Weasley', 1, 'McGonagall');
```

### Senza titolo e senza modifiche

Il pannello lo chiama «blocco N», dalla sua posizione fra i blocchi SQL della pagina
(il blocco `hideQuery` conta).

```sql live dataset=archivista/registro-punti
SELECT count(*) AS assegnazioni FROM assegnazione;
```

### Un altro dataset

Il pannello mostra comunque l'ultimo blocco eseguito e nomina il dataset in testa.

```sql live dataset=archivista/biblioteca title="La biblioteca"
INSERT INTO autori (nome, paese) VALUES ('Bathilda Bath', 'Regno Unito');
```
